# Magpie 路由选择

[English](MAGPIE-ROUTING.en.md) | 简体中文

当前定位:此包是此前的硬编码路由原型,尚未接入 iOS。按新的 [标准 API 与插件分层](AI-CORE-BOUNDARY.md),Core 保留候选校验与策略执行机制,具体路由策略改为由插件提供;本页记录原型行为,不表示已经实现 Magpie 路由插件兼容,也不将它作为标准 API 的必经调度器。

更新:2026-10-31。`magpierouting` 决定一次请求由哪个供应商账号与模型回答。它是纯函数:不联网、不读系统时间,网络和时间都由调用方传入,所以同样的输入必然得到同样的计划。

## 为什么在 Core 里

原版 Magpie 自己跑一个本地网关,路由发生在它的进程里。iOS 把插件运行时嵌进 App,没有那个网关,所以选择必须在共享层做一次,而不是每个客户端各写一遍。桌面端首期连接本机安装的 Magpie,用不到这个包;iOS 用它。

## 决策顺序

1. **硬条件**:视觉、工具、推理、上下文长度、协议方言。不满足的候选被**移除**,不是排在后面 —— 没有视觉的模型无法"稍微处理一下"图片。
2. **任务档位**:难度(简单/普通/复杂)映射到允许的模型与供应商;显式指定的模型不受档位影响,也不会被替换成别的模型。
3. **可用性**:已过期的订阅不参与;额度用尽的窗口按模型剔除;冷却中的账号仍然可用但排到最后;需要处理的登录状态直接排除。
4. **策略排序**:可选的"先用即将到期"、"选便宜的"、会话黏性。最后用供应商/账号/模型名做稳定兜底,保证可复现。

## 几条容易写错的地方

| 规则 | 为什么 |
|---|---|
| 未报告的额度不是 0 | "不知道"与"用完了"在配额卡上读起来完全不同;把未知当 0 会挑错账号 |
| 自动续费的订阅不参与"先用即将到期" | 它没有会浪费的额度,按到期日排序会把它误判成即将失效 |
| 冷却中的账号仍可回答 | 没有健康候选时,一个正在冷却的账号也好过直接失败;排序把它放最后 |
| 显式选择的模型绝不被替换 | 悄悄换模型比失败更糟:用户以为问的是 A,回答来自 B |
| 只说方言为空的模型不被排除 | 沉默不是拒绝;只有明确声明了别的方言才排除 |
| 每个模型的额度窗口优先于通用窗口 | 供应商按模型计量时,通用窗口不能代表某模型已用尽 |

## 验证

`go test ./magpierouting` 覆盖上述每一条,并额外验证计划可复现(同一输入 20 次顺序不变)。当前覆盖率 92.8%。命令与输出留在 CI 与本地日志里,不在这里复述数字以外的结论。

尚未完成:`magpierouting` 还没有接到客户端;iOS 侧的分类器(判断难度)、真实用量采集、以及把计划传给 `magpieplugin` 发请求,都还没有实现。这个包现在只提供"给定目录与状态,选出候选"这一层的可靠行为。
